# 实验协议与防泄漏边界

## 数据与切分

MIND-small：65,238 篇合并去重新闻，原始 train 156,965 个 impressions、dev 73,152 个 impressions。根据 train 的时间戳选 90% 分位时间，严格早于边界为训练集（141,265），其余为内部验证（15,700）。官方 dev 作为留出评测。

每个 impression 保留全部候选和点击标签，多次点击不强行排序。生成训练将同一 impression 的每个点击视为共同历史下的独立正目标，不伪造 impression 内的点击先后顺序。原始 history 截取最近 20 项。

编码器固定，无标签微调；码本仅拟合训练时间边界前出现的文章。dev 新闻可以在推理时用固定编码器/码本编码，不更新码本。热门和 ItemCF 的拟合仅使用内部训练区间。

MIND 无准确发布时间。全目录召回采用“首次日志出现时间严格早于请求”的可用性代理，排除该请求中才首次出现的文章，已读条目也过滤。**所有真实正目标仍计入 Recall 分母**，不可用目标不通过删除来提高结果。这个协议不是精确生产目录复现，报告该限制。

## 训练

生成器：3 层、128 维、4 heads，约 63 万参数，3×32 SID token，加 BOS/PAD/SEP；自回归监督只计算目标 SID 三步的交叉熵。正目标 212,477 个，batch 256，AdamW 3e-4，3 epoch，内部验证 loss 选择检查点。

DNN：固定文本向量，历史与候选点积注意力，候选/兴趣/逐元素乘积以及相似度、最近兴趣、类别匹配、历史长度特征，128→64→1 MLP。BCE，AdamW 1e-3，batch 2048，3 epoch。每个正样本最多抽取 4 个真实未点击曝光，采样会改变基准率，因此输出是排序分数，**不是校准 CTR**。

全训练累计热度/ItemCF 会对训练行造成未来标签泄漏，因此 DNN 训练和推理都屏蔽这两列。召回阶段仅在训练边界之后使用训练统计，合法。

## 对照与改进

召回：热门、ItemCF、内容向量、SID 生成；传统 RRF、固定四路 RRF、基于历史长度门控的四路融合。生成语义前缀扩展与完整三层 SID 桶展开比较，观察新内容覆盖。各召回输出上限 100、融合候选上限 100；相同输出预算不代表相同计算成本，单独记录延迟。

门控的历史阈值与生成权重仅从 300 个内部验证 impressions 选择，以 Recall@50 为目标；测试时冻结。当前门控不含训练得到的置信度/兴趣集中度网络，这属于后续扩展。

排序：热门分数、内容相似度、DNN；分别提供推理时屏蔽个性化和完全重新训练的无个性化消融（seed 42）。端到端比较完整召回+DNN 与去生成召回+DNN，使用全正目标分母。

## 指标口径

- impression 排序：逐 impression AUC、MRR、NDCG@5/10 再平均。MRR 使用 MIND 的多正例平均 reciprocal rank 定义。单类 impression 的 AUC 为 null 并跳过，不设成 0.5。
- 全目录召回：Recall@20/50、catalog coverage、首次出现在训练边界之后的新文章 Recall@50、端到端 NDCG@5/10。
- 互补性：生成前缀与传统候选 Jaccard，以及传统召回之外的独有正命中数。
- 初轮全量排序 73,152 行；召回为固定随机抽取 1,000 行，样本 ID 随预测明细保存。每个结果标注分母。
- 三个种子分别训练 SID/DNN；相同采样 ID 对比，汇总均值与标准差。实验未完成时 summary 标记 missing，不填估计值。

## 在线与历史严格分开

MIND 只证明历史日志上的效果。HN 内容、用户 ID、反馈库完全独立；默认线上策略是内容兴趣与新鲜度。MIND 权重的 HN 推理入口只能标记为跨域研究实验。HN 样本未满足训练/验证条件时不能宣称有在线 DNN 收益；自动化事件不进入真实 CTR。

检索没有真实 query relevance 标注，因此仅做功能/延迟验收，不捏造搜索 NDCG。项目不包含广告竞价或转化标签，没有广告效果实验。

## 2026-10-29 修复后的 HN 在线协议

1. 默认推荐生成时，在同一个数据库读事务中读取用户兴趣、历史及协同信号。历史和协同行为的时间不得晚于请求时间。`request_snapshots` 与返回列表一同提交，保存最近 20 条历史、兴趣、实际用于在线排序的 1158 维特征，以及包含兴趣、热度、新鲜度、协同和已读惩罚的完整内容分数。文章或用户偏好后续变化不重算旧特征。
2. 标签定义为请求后 `[0, 24h)` 内是否点击；曝光也必须在这个窗口内，窗口结束后请求才成熟。点击先于曝光到达仍可以标正，但不进入该请求的输入特征。24 小时之后的点击不回填该次标签。测试事件、搜索、收藏页、研究策略、没有快照的历史请求和不兼容快照均排除，报告排除计数。
3. 按**推荐请求时间**取末 20% 请求作为验证候选；同一请求、同一时间戳不拆分。训练请求的完整标签窗口必须在验证开始时结束，跨边界请求剔除。已有模型的 `data_until`（含其晋升验证窗口）之后才允许取新的验证请求，避免重复消费同一验证集。样本或时间间隔不足时直接返回不足状态。
4. 候选仍为现有 `Ranker`，seed 42，AdamW 1e-3，5 epoch。没有新增模型或更换整体架构。默认门槛仍为 1,000 次成熟曝光、50 次正曝光，验证至少 20 个同时含正负例的请求。
5. 无已部署在线模型时，用请求快照中**完整内容策略分数**比较；已有模型时，加载经过校验的当前模型，对同一批验证请求的同一组特征重新打分。晋升条件仍为 NDCG@10 严格更高且 AUC 不下降。单类请求同时从双方指标中排除，分数相同时按原展示位置排序。缺少已有模型训练时间证明、模型校验失败，或训练期间部署指针改变，都不能自动发布。
6. 保存候选权重、manifest、训练损失、训练标签截止时间、验证开始时间、数据截止时间及逐请求双方预测。比较范围是**实际曝光条目上的排序**；没有未展示条目的反事实标签，不等价于全目录召回收益或线上 CTR 因果提升。

旧在线训练和晋升实现的评估值不得作为修复后的质量依据。复现延迟曝光问题可使用 `scripts/review_online.py`；它只在指定的新建独立目录生成合成反馈，结果必须标记为回归实验。实际结果与对比见 [REVIEW_FIXES.md](REVIEW_FIXES.md)。
