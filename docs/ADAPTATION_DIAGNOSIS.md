# ColdFuse 性能瓶颈：旧样本诊断

此处只分析已使用过的 `coldfuse-v2`，不作为新方法的独立验证证据。命令：

```bash
.venv/bin/python scripts/diagnose_cold.py --baseline artifacts/coldfuse-v2 \
  --output artifacts/adaptation-v1/reports/baseline_diagnosis.json
```

## 已由代码与预测共同支持

1. **低历史数不等于内容信号应该让位热门。** `coldfuse.state/weights` 用 `n/(n+3) × norm(平均历史)` 同时衡量证据量和主题一致性；主题增加时平均范数下降，导致1/3/5/10条的平均内容权重只有 .500/.645/.661/.658，热门却为 .850/.807/.802/.803。模型把多兴趣用户同时当作不可信用户，门控并未随行为数持续增强。这是已确认的实现行为；是否应采取别的权重由新验证检验。
2. **生成通道几乎无法独立进入融合池。** 无兴趣5条时平均生成权重 .02486、beam集中度 .06752。RRF中其第一名的未归一化分数约 .02486/61=.000408，而热门第100名约 .80156/160=.00501，差一个数量级。该例解释为何只有重叠候选容易存活，不意味着每条请求都使用均值。内容/SID候选平均Jaccard约 .06249，SID独有命中贡献约 .01207（所有正例分母），却没有转化为完整－去生成的Recall50增益。
3. **候选截断先于DNN。** `cold_experiments.compose`、`ColdFuse.recommend` 只重排融合100个候选。全曝光DNN的AUC可以提高，仍无法找回被截断的候选。当前主要损失发生在融合截断；盲目扩大DNN不直接解决这个问题。
4. **训练目标与部署候选分布不同。** `cold_training.arrays` 每请求使用全部正例与最多4倍曝光负例，训练BCE；不是全目录召回损失，也未从实际检索候选构造难负例。`blend` 将未校准sigmoid与归一化RRF相加，其尺度没有独立校准。它们是设计限制，不能从当前结果单独断言因果贡献。
5. **代理先验容易覆盖首条阅读。** `state` 的固定收缩在n=1时保留75%先验；先验来自粗类别原型，未检查与新阅读的冲突。`matrix`的候选注意力只发生在精排阶段，内容召回仍只有一个平均向量，不能恢复在召回阶段丢失的次要主题。
6. **CF支持度与可信度混同。** `cf_support=len(正CF候选)/100`，不是支持用户数或置信区间；满100候选即可饱和。新文章CF为0、热门统计冻结造成时效与覆盖限制，不代表协同方法本身普遍无效。

## 下一步可证伪假设

- 去除有信号用户的热门竞争，并保护内容基准，可能减少融合损失。
- 历史最大相似度可保留次要主题，但也可能放大偶然点击；必须和中心表示、最近行为及去多兴趣消融比较。
- 先验/观测一致性可以抑制冲突代理，但同样可能错误拒绝真实兴趣转移。
- 侧路与内容的重叠是便宜支持代理，也可能抑制互补性；因此保留固定侧路权重、去侧路、去生成对照，不能只报告保守策略。

以上不是新实验结论。选择、准入、最终留出相互隔离，协议见 [ADAPTATION_PROTOCOL.md](ADAPTATION_PROTOCOL.md)。
