# 记录成本有界优化：结果与停止决定

**停止继续优化和线上接入。** 两项优化使新增记录开销p95由同轮文件基线的78.56ms降为54.88ms，但仍超过冻结的10ms门槛。逻辑载荷大小达标，计入WAL/索引的单事务文件增长检查未达标。没有新增自然用户反馈，没有推荐收益证据；内容策略、回退及每日观察器保持原状。

本轮基线 `24e974c`；协议与剖析 `edeb8da`；两项实现 `fe5fb2b`；报告器修正及正式验收 `f4e53f0`。协议见 [REPLAY_V6_PROTOCOL.md](REPLAY_V6_PROTOCOL.md)，实现前固定选择见 [REPLAY_V6_DECISIONS.md](REPLAY_V6_DECISIONS.md)。完整机器证据见 [replay_v6_evidence.json](replay_v6_evidence.json)。本轮没有第三项优化、扩大搜索、改门槛或远程推送。

## 成本瓶颈与两项改动

在v5冻结目录和相同120个合成请求上，cProfile得到以下每请求平均时间：

| 部分 | 平均ms | 解释 |
|---|---:|---|
| fsync系统调用 | 52.286 | 文件和目录同步合计 |
| catalog_rows | 17.513 | 含逐行字典构造与NumPy有限值检查 |
| SQLite execute | 0.821 | 原推荐的数据库查询 |
| canonical | 0.521 | JSON序列化调用 |

剖析会改变时间，累计函数还可能嵌套，不能相加或直接用作延迟验收。原始每请求函数统计保留在 `artifacts/replay-v6/profile/profile.json`。

据此只实施：

1. **批量目录校验。** 将逐行NumPy有限值检查改为一次批量检查，仍逐请求比较元数据，保留删除、负分、非有限值和重复ID拒绝。没有仅凭可变list对象身份跳过检查。
2. **同步事务日志。** 新增隔离 `SQLiteReplayStore` / `SQLiteReplayReader`。目录仍使用内容寻址文件，请求完整载荷在独立SQLite WAL事务中写入，`synchronous=FULL`，提交完成后才返回确认。保留默认1000页自动checkpoint，另测显式checkpoint成本。没有异步队列、弱同步或生产数据库迁移。

SQLite在FULL模式下对每次WAL提交进行同步，依据[官方同步级别说明](https://www.sqlite.org/pragma.html#pragma_synchronous)；WAL与主库共同构成持久化状态，复制活动日志应使用一致性备份，不能只复制主库。[官方WAL说明](https://www.sqlite.org/wal.html) 本轮SQLite版本3.53.1。工程实现沿用标准事务机制，不主张提出新的推荐算法或持久化理论。

## 存储、冷启动与正确性

| 验收项 | 实测 | 决定 |
|---|---:|---|
| SQLite新增记录开销p95≤10ms | 54.88ms | 未通过 |
| ≤20条历史的逻辑载荷≤32KiB | 最大11,236字节 | 通过 |
| 本轮实现前增加的WAL/索引文件增长检查≤32KiB | 最大37,080字节（36.21KiB） | 未通过 |

≤20条历史的每事务文件增长p50/p95为20,600 / 37,080字节；三种记录器逻辑载荷相同。不能只报载荷或主库大小而忽略WAL写放大。文件长度与实际分配磁盘块分别记录在JSON；主机文件系统预分配行为不应被当作每请求逻辑大小。

121条已确认记录（含1条预热）在显式checkpoint前的主库/WAL/SHM分别为4,096 / 2,653,312 / 32,768字节；扣除初始化，平均每条增长21,859.83字节。checkpoint耗时64.25ms，完成后主库1,105,920字节、WAL归零、SHM32,768字节。未关闭自动checkpoint，但本次WAL未达到1000页阈值；显式checkpoint成本单列，不宣称覆盖长时间运行中的尾延迟。目录文件成本与请求存储分开，继续共享原3,594,164字节目录。

三路首次目录登记耗时418.40 / 833.70 / 277.06ms，均为单次测量，不能据此给出稳定顺序。SQLite驻留目录重放p50/p95为5.30 / 5.85ms；新Reader首次加载并重放39.66ms，未清除操作系统页缓存。

三种记录器各120/120请求均与冻结推荐源码的top100及对应分数完全一致，也通过完整分数哈希校验。未来修改目录文本/分数/向量、增删文章、兴趣和反馈后，各120条旧记录仍能独立重放。未改内容推荐公式、候选预算或返回顺序。

故障回归覆盖：同一记录器与独立记录器的并发写入、重复ID拒绝、载荷损坏、提交前后强制终止子进程、SQLite页数上限诱发的 `SQLITE_FULL`、文件fsync注入 `EIO`。提交前终止不留下部分请求，提交后终止不丢确认记录；重启后integrity_check通过。写入失败抛错且不更新成功凭证，普通内容推荐仍可运行。这些是进程崩溃/故障注入验证，不是物理断电或实际耗尽整块磁盘的试验。
