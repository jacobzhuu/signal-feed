## 真实阅读入口

在服务器本机的浏览器打开：

```text
http://127.0.0.1:8765
```

在另一台已经有SSH访问权限的电脑，保留原有SSH账号、主机别名和认证方式，在该电脑终端执行：

```bash
# 将 <已有SSH主机别名> 替换为平时能正常登录此服务器的别名；不要原样粘贴尖括号。
ssh -N -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 \
  -L 127.0.0.1:18765:127.0.0.1:8765 <已有SSH主机别名>
```

保持终端运行，在同一台电脑浏览器打开 `http://127.0.0.1:18765`。Ctrl-C只关闭本次转发，不停止网站。该命令只在客户端本机监听，不新增服务器公网监听。本轮仅使用本机OpenSSH的 `-G` 验证选项解析，未建立SSH连接；客户端是否允许转发、具体别名和登录权限仍需由已有权限的人实际确认。没有为试点申请账号、共享密码或修改SSH配置。

如果18765被占用，选择另一个未占用的客户端端口，并同步修改浏览器地址；服务器目标仍是127.0.0.1:8765。若提示转发被禁止，记录该错误并停止入口验证，不擅自更改服务器SSH权限。若页面空白，保留发生时间、浏览器错误和失败URL即可，不提交Cookie、密码或整份认证头。

## 技术检查与真实阅读必须分开

浏览器动作测试只使用8768隔离服务；远程检查可另开客户端转发：

```bash
ssh -N -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 \
  -L 127.0.0.1:18768:127.0.0.1:8768 <已有SSH主机别名>
```

确认 `http://127.0.0.1:18768/api/health` 的 `test_events=true` 后，才进行指定曝光、点击、收藏检查。**使用独立浏览器配置或独立自动化context，与真实阅读配置分离；仅分端口或分标签页不够。** Cookie按主机而非端口隔离，同名Cookie可能互相覆盖，导致真实阅读产生新的匿名身份。现有隔离回归已在独立context验证事件落库，不必再对生产重复点击测试。

自然阅读使用固定浏览器配置，不为了凑“冷启动”清Cookie或反复新建身份。真实端不执行任务式点击/收藏，不将一次功能检查解释成自然偏好。试点期间保持默认内容页面，研究入口不是试点任务；搜索等行为按原规则单列。
