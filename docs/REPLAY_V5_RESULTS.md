# 全目录重放：隔离工程结果与停止决定

**重放一致性通过，记录延迟未达标，原型保持关闭；没有新的推荐收益证据，也不部署新策略。** 基线 `cc144ad`；实现与测量协议提交 `c1d6296`。本轮完成约定的两个数据源审查及最小重放原型，不启动新的算法搜索或生成配额研究。

数据源结论见 [NEWS_SOURCE_V5_AUDIT.md](NEWS_SOURCE_V5_AUDIT.md)：EB-NeRD有未来活动筛选，Adressa有历史左截断和曝光标签缺口。本轮没有得到可以直接验证自然冷用户稳定收益的独立数据。已有 [v3负结果](INTEREST_V3_RESULTS.md) 与 [v4采集窗口](TEMPORAL_V4_PROTOCOL.md)继续冻结，不扩大参数搜索或调整统计门槛。

## 实现与一致性

`ContentService.recommend(..., replay=store)` 只有显式传入记录器且处于测试环境才可使用；网站API没有传入它。仅覆盖无搜索、无在线DNN的 `content-v1`。记录保存请求当时目录版本、文章元数据、384维向量与编码器版本、显式兴趣向量、原始行为计数、完整去重历史与实际最后20条有效历史、完整稀疏协同计数、策略源码哈希、分数哈希、top100与返回列表。

目录按内容寻址复用。相同只读目录对象只核对元数据，不在每次请求重新散列、复制全部向量；首次登记校验文件后持久化。目录原子发布，请求独占写入并fsync，旧记录不能覆盖。重放从历史目录和请求输入重新计算全目录分数，不访问后来的数据库或目录。历史文章仍按原策略降权；目录外协同计数仍参与原归一化。这里“全目录”指该次服务实际使用的目录，不能解释为整个HN。

在真实HN目录的 **2,006篇文章** 上，用现有冻结MiniLM编码器与隔离合成用户验证。历史0/1/3/5/10/25各20个请求，共120个；每组一半有显式兴趣。合成协同事件仅写隔离库，任何结果都不是自然用户效果证据。

| 验证 | 结果 |
|---|---:|
| 与 `cc144ad` 原始源码的top100及对应分数完全一致 | 120/120 |
| 当前未记录与记录推荐的实际top30一致 | 120/120 |
| 重放全目录分数哈希、top100与实际捕获一致 | 120/120 |
| 未来增加反馈、修改兴趣、增删文章、改文/分数/向量后旧请求仍可精确重放且文件未改 | 120/120 |
| 测量请求共享初始目录版本 | 120次复用1个版本 |

重放会拒绝损坏或缺失文件、源代码/编码器合同不符、错误预算、错误历史次序和可写目录向量。额外测试覆盖重复行为、目录外历史、目录外协同归一化及25条原始行为与20条有效历史的区别。源代码与NumPy版本有绑定；精确分数校验仍依赖数值环境，不保证跨BLAS或硬件逐位一致。

独立实现贡献在于把现有推荐的隐含状态变为可校验的历史记录，并以目录版本共享控制存储；这是工程实现，不是新推荐算法或新聚类理论。不能将重放成功称为兴趣适应有效。

## 实际成本与门槛

Intel Xeon Gold 5220R共享主机，Torch 2线程、BLAS 1线程；120个请求轮转未记录/记录/重放的测量顺序，没有推荐结果缓存。保留现有显式兴趣编码缓存。为允许重放先测，每个请求先在计时外准备一份相同输入记录；测量捕获另写新记录，逐次原始数据全部保留。

| 预先冻结的原型门槛 | 结果 | 决定 |
|---|---:|---|
| 新增记录开销p95 ≤10ms | 78.62ms | 未通过 |

全部历史组的单请求p50/p95为8,033.5 / 11,959.25字节，最大12,081字节。一个初始目录版本3,594,164字节（3.43MiB），120次请求复用；若每请求复制目录则仅目录部分就需431,299,680字节（411.32MiB）。未来变更另生成3,594,183字节的新版本。保存的预热、准备记录和变更测试记录均未删，只是不计入120个测量请求的延迟统计。

模型加载及目录编码初始化11.04秒；首次目录登记213.14ms；新建Reader并校验加载目录后首次重放66.42ms。这些是各一次单独测量；没有清除操作系统页缓存。进程峰值RSS945.67MiB含编码器和前后对照对象，不是记录模块独占内存。小目录、顺序流量不支持对88,053篇目录或高并发容量作外推。

同步元数据检查、序列化、文件和目录fsync都包含在新增成本中；本轮没有分项剖析，不能断言某一项占比。**按照冻结协议停止在原型阶段**，不降低持久性、放宽10ms门槛或追加优化搜索以改变本次判定。

## 回归、证据与运行状态

90项Python、10项Playwright、前端构建及Ruff全部通过；Python只有已有的Starlette/AnyIO弃用提示。验收和成本测量使用相同的干净提交 `c1d6296`，源码SHA256为 `d08d1334106aba0bfdf24b55769a98d1b2d4cb24c0e8bedc0caaa6ac85df6465`。后续提交仅增加报告与证据。

最初的目标测试出现过1项失败：模拟存在DNN而版本为空时，版本拼接先于原型拒绝检查。已把拒绝检查前移，在阶段提交前重跑20项目标测试通过；最终全量回归覆盖该路径。另有一次新增脚本变量名的Ruff失败，已修正。开发失败记录与正式成本负结果均保留。

291份旧研究文件哈希全部一致；没有覆盖v3/v4及更早冻结结果。机器可读来源审查、全部分组成本、回归及产物校验和见 [replay_v5_evidence.json](replay_v5_evidence.json)；原始逐请求计时、两个目录版本、记录文件、冻结输入库和完整日志保存在 `artifacts/replay-v5/`。匿名活动原始文件留在本机保护目录，不进入Git。

生产PID `3683350`、隔离服务PID `3676922` 与观察器PID `24292`均保持原启动时间。本轮未重启服务，未改前端、API路由、数据库结构、策略或模型指针，也未向生产写入合成事件。运行状态通过进程与监听端口核对；本轮没有新增生产API探测请求。浏览器回归仅访问8768隔离服务。

现在持续运行的是每日只读反馈审计，不是算法效果实验。观察器保持原冻结源码与窗口，北京时间每日08:10读取一次，到2026-11-23 08:10最后采集后停止。`full_catalog_replay_supported=false`、`efficacy_authorized=false`继续成立：隔离原型成功不等于真实请求已采集完整记录。

## 复现与后续边界

使用已冻结的目录输入可避免实时文章更新改变基准；所有新运行必须换输出目录。原始基线源码由脚本从Git读取，环境版本与编码器版本见证据JSON。

```bash
# 当前代码或c1d6296；读取冻结目录副本，只在新目录构造合成反馈
.venv/bin/python scripts/benchmark_catalog_replay.py \
  --db artifacts/replay-v5/benchmark/catalog-input.sqlite \
  --hf-home /data1/zhuzy/signalfeed/hf \
  --output artifacts/replay-v5/benchmark-NEW

# 验收必须在源码固定时运行；8768须为现有隔离测试服务
SIGNALFEED_HOME=/data1/zhuzy/signalfeed/replay-v5/engineering-NEW \
SIGNALFEED_BASE_URL=http://127.0.0.1:8768 \
  .venv/bin/python scripts/verify.py --browser
```

本轮没有可用于收益检验的新自然用户数据，不对合成用户运行显著性检验，也不重复检验旧test。既有用户级统计、消融与停止结论仍见v3报告。只有纯兴趣适应在新独立数据上获支持，才考虑生成式召回配额融合。

后续可独立安排一次有界的记录成本剖析，区分目录检查和持久化写入，再评估目录刷新时预登记、批量持久化等工程方案；任何异步方案都须先定义崩溃时记录完整性、积压处理、保留期限和失败回退，再用新测量验收。当前没有启动这些优化。效果研究则等待满足条件的真实成熟反馈或另行准入的数据，先冻结新的独立协议与功效设计。闭窗不足照原协议记录，不自动延长或降低要求。

**部署决定：维持现有内容基线与回退；记录原型关闭，新算法与生成融合均不发布。本轮无远程推送。**
